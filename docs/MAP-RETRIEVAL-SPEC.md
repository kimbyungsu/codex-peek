# 요청 기준 지도 검색 — 구현 전 확정 명세 v1

[설계 문서](MAP-RETRIEVAL-DESIGN.md)가 *"코드를 쓰기 전에 다섯을 정하라"*고 남긴 항목을 값·규칙까지 확정한다.
**대부분의 값은 기존 코드에서 가져왔다.** 근거 없이 정한 값은 그 자리에 정직하게 표시했다.

## 1. 재입증 typed 계약

### 허용 관계 종류

지도가 이미 쓰는 열두 종류를 그대로 쓴다([project-map.ts:29](../src/project-map.ts) `RELATIONS`).
**새 종류를 만들지 않는다** — 지도에 못 넣을 관계는 재입증해도 쓸 데가 없다.

**이름으로 분류하지 않는다(검증 지적).** 관계마다 **증명 어댑터가 있을 때만** 기계 판정하고,
어댑터가 없으면 종류와 무관하게 **제안으로 내린다.** 지금 어댑터는 둘이고, 나머지 열 관계는 제안 단계에 머문다.

이름 고정 분류가 틀린 이유 — 같은 설정 키를 각자 읽는 두 파일은 `produces`/`consumes`가 **아닐 수 있고**,
`validates`는 실제 제어 흐름을, `stores`/`mutates`는 쓰기 효과를 봐야 한다. 반대로 어떤 관계는 메타데이터만 있으면 기계로 확인될 수도 있다 — 다만 장부의 `newSig`는 그 자리에 못 쓴다(아래).

| 어댑터 | 입력 | 지원 | 성공 조건 | 실패·미지원 |
|---|---|---|---|---|
| `import-parse` | 양 끝 경로 | JS·TS만(`collectInventory`와 같은 정규식 수준) | 정적 import 그래프에 그 방향 간선 실재 | `unknown` |
| `call-parse` | 양 끝 경로 + `symbol` 필수 | JS·TS만 | 호출 지점이 실재하고 심볼이 일치 | `symbol` 없으면 `unknown` |
| **없음** | — | — | — | 나머지 관계 전부 → **제안만** |

**두 어댑터 모두 실패하면 `unknown`이고, `unknown`은 성공이 아니다** — 격리 유지다.
정규식 수준 판독의 한계(배럴 재수출·경로 별칭·동적 참조)는 그대로 남으므로,
확신 못 하면 `unknown`으로 떨어뜨린다.

⚠ **`meta-supersede`를 뺐다(검증 지적).** 장부의 `newSig`는 **관찰 항목의 대체 서명**이지
([ledger-events.ts:41](../src/ledger-events.ts)) Project MAP의 **두 node 사이 `supersedes` 간선을
증명하지 않는다.** 그대로 근거로 쓰면 엉뚱한 후보가 뽑혀 동봉된다.

**어댑터를 먼저 만들지 않으면 그 관계는 제안 단계에 머문다.** 그게 맞다 —
증명 못 하는 것을 증명했다고 하는 것보다 낫다. 어댑터는 필요할 때 하나씩 추가한다.

### claim 형태

```
{ relation: <RELATIONS 중 하나>,
  from: { path, symbol? },
  to:   { path, symbol? },
  direction: "from→to" }
```

셋 중 하나라도 못 뽑으면 **변환 실패 = 격리 유지**. 자유 문장을 억지로 끼워 맞추지 않는다.

### evidence 형식

```
evidence: [{ file, locator, quote, contentHash }]
```

- `file` — 현재 대상 기준 상대경로
- `locator` — 줄 번호 또는 줄 범위
- `quote` — 그 자리에서 실제로 읽은 발췌
- `contentHash` — 그 파일 전체의 지문

**양 끝 각각 최소 1건**, 합쳐 **최대 4건**. P8 보강이 쓰는 형식과 같다.

### 판정 순서

1. 그 관계에 증명 어댑터가 있는가 → 없으면 제안만
2. 양 끝 경로가 현재 대상에 실존하는가 → 아니면 격리
3. 어댑터 판정이 성공인가 → unknown·실패면 격리
4. **기록 직전** target identity · basis · 모든 `contentHash` 재대조 → 하나라도 어긋나면 **기록 안 함**
5. 성공 → `legacyEventHash`를 참조로 단 **새 제안** 생성. 옛 횟수 복사 없음

## 2. 사건 종류별 provenance 스키마

### 중앙이 채운다 (`appendLedgerEvent` 안에서)

| 필드 | 값 |
|---|---|
| `eventId` | 새 난수 16자리 |
| `originRepoKey` | **아래 `targetIdentity`** — 경로 해시가 아니다 |
| `ts` | 기록 시각 |

### ⚠ `targetKey`를 경로 해시로 두면 안 된다 (검증 blocker · `ab-1`)

현행 `wsKeyFor`는 **정규화된 경로 문자열의 해시**이고
([contract-lib.js:1993](../bridge/contract-lib.js)) 정규화에 `realpath`도 저장소 세대도 없다
([contract-lib.js:978](../bridge/contract-lib.js)). 정찰 대상 해석도 `path.resolve`까지다
([contract-lib.js:2039](../bridge/contract-lib.js)). 그래서 둘이 깨진다.

- 같은 저장소를 **심볼릭 링크와 실제 경로**로 열면 **서로 다른 키**가 된다
- **더 위험하게** — A 저장소가 있던 **같은 경로를 B 저장소로 갈아끼우면 키가 그대로**다.
  그러면 옛 A 사건의 `targetKey`와 지금 B의 `targetKey`가 같아 **재대조를 통과하고 A 사건이 B 장부에 남는다**

**저장소 정체성으로 바꾼다.**

```
targetIdentity = 해시( realpath(대상) + "\0" + repoGeneration )
repoGeneration = git 저장소면  최초 커밋 해시(root commit)
                 git 아니면    .codex-bridge에 처음 기록한 UUID(대상 폴더에 저장하지 않음)
```

⚠ **realpath + root commit도 안 된다(검증 blocker).** 넷이 깨진다.

| 경우 | 무엇이 깨지나 |
|---|---|
| **포크** | 원본과 포크가 **같은 root commit** — 서로 다른 저장소인데 같은 정체성 |
| **shallow clone** | root commit에 **도달할 수 없다** |
| **빈 저장소** | 커밋이 **없다** |
| **폴더 이동** | `realpath`가 바뀌어 **같은 저장소가 다른 정체성**이 된다 |

**저장소 안에 정체성을 심는다.**

```
위치     = git이면  `git rev-parse --git-common-dir` 결과 디렉터리 안의 codex-peek-identity
           (worktree·서브모듈의 .git은 디렉터리가 아니라 gitdir 파일일 수 있으므로 경로를 직접
            조립하지 않는다 — 기존 basisFor가 같은 방식으로 git을 호출한다: map-bootstrap.js:168~)
           git 아니면  대상 폴더의 .codex-peek-identity
repoIdentity   = 그 파일에 처음 1회 기록한 UUID
targetIdentity = 그 UUID
```

**파일 계약 세 가지(검증 blocker — 이것 없이는 정상 경합에서 출처가 갈라진다):**

1. **원자 공개** — 최종 이름에 직접 쓰지 않는다. **같은 디렉터리의 임시 이름에 UUID를 완성 기록한
   뒤, '대상이 이미 있으면 실패하는' 원자 연산으로만 공개한다**(예: `link` 후 임시 삭제 —
   단순 rename은 POSIX에서 기존 파일을 조용히 덮으므로 단독으론 쓰지 않는다). 기존 `atomicWrite`가
   같은 이유(부분 기록 노출 차단)로 임시+원자 교체를 쓴다([contract-lib.js:90~108](../bridge/contract-lib.js)).
   공개 실패(대상 실존)=경합 패자 → **승자 파일을 재판독해 그 값을 쓴다.**
   부분·빈 파일은 최종 이름에 존재할 수 없고(공개가 원자), **기록 중 강제 종료의 잔재는 임시
   이름에만 남아** 판독 대상이 아니다 — 중단 후 재시작해도 다음 공개 시도가 그대로 성립한다.
   임시 이름은 기존 atomicWrite와 같은 PID+난수 규칙([contract-lib.js:96](../bridge/contract-lib.js))으로
   충돌을 피한다. **잔재 정리는 원자 공개의 무결성에 필요하지 않으므로 이 명세는 규정하지 않는다**
   (정리를 구현하려면 활성 작성자 파일을 건드리지 않는 조건을 그때 별도로 정한다)
1-1. **판독 형식 검증** — 최종 파일 내용이 UUID 형식이 아니면 손상 = 정체성 `unknown`(계약 2와
   동일 처리). **자동 삭제·재생성은 하지 않는다** — 잘못 덮으면 과거 귀속이 통째로 갈리므로 사람 확인 몫
2. **판독 불가(권한 등) = 정체성 `unknown`** — 귀속이 필요한 기록은 **거부하고 사유를 남긴다.**
   오귀속보다 미기록이 낫다
3. **지워졌다 다시 생기면 새 정체성** — 이전 사건은 이전 정체성에 남는다(사람이 가른 것으로 취급)

- **폴더를 옮기거나 심볼릭 링크로 열어도** 같은 값 — 파일이 저장소를 따라다닌다
- **빈 저장소·shallow에서도** 그냥 만들면 되므로 작동한다
- 같은 경로에 **다른 저장소를 갈아끼우면** 그 저장소엔 파일이 없거나 다른 UUID라 **값이 달라진다**
- **포크·클론은 이 파일을 얻지 못한다** — `.git/` 안의 임의 파일은 clone·fork에 복사되지 않는다.
  따라서 **사본은 새 정체성**이고 장부도 따로다(대개 다른 기계이므로 자연스러운 경계다).
  ~~클론이 파일을 복사해 같은 값이 된다~~는 직전 판의 서술은 **Git 실동작과 달라 폐기**(검증 지적)

기존 `wsKeyFor`는 **파일 이름 짓기에만** 계속 쓴다. **귀속 판정에는 쓰지 않는다.**

**호출자는 이 셋을 줄 수 없다.** 주더라도 중앙 값으로 덮는다 — 생산자가 여럿이라
([scout-providers.js](../scripts/scout-providers.js) · [extension.ts](../src/extension.ts) ·
backfill · note · reconcile · migrate) 일부만 채우면 다시 추정에 의존하게 된다.

### 호출자가 준다

**현행 사건 종류를 빠짐없이 적는다**([ledger-events.ts:13~](../src/ledger-events.ts)).
직전 안은 여덟 종을 빠뜨렸고, 대시보드가 그것들을 정상 생성한다([extension.ts:4018](../src/extension.ts)).

| 사건 종류 | 필수 | 선택 |
|---|---|---|
| **제안** `proposed` | `sig` · `basis` · `evidenceFp` · `evidence` | `text` · **재입증 유래면 `legacyEventHash`·`importedFrom` 필수**(완료 키 재개 판정이 이 필드로 돈다) |
| **동봉** `attached` | `sig` · `subjectRef` | `from` |
| **검증 파생** `confirmed`·`refuted` | `sig` · `subjectRef` · `grade` · `cited` · `seen` · `echoed` · `askId` | `from` |
| **사람 판단** `user_confirm`·`user_dispute` | `sig` · `subjectRef` | `from` |
| **사람 오버라이드** `pinned`·`unpinned`·`banned`·`unbanned` | `sig` · `subjectRef` | `from` |
| **별칭** `alias`·`unalias` | `sig` · `subjectRef` · **`aliasSig`** | `from` |
| **수명** `superseded` | `sig` · `subjectRef` · **`newSig`** | `from` |
| **수명** `tombstone`·`exported` | `sig` · `subjectRef` | `from` |

⚠ **`attached`에 `grade`·`cited`·`seen`·`echoed`·`askId`를 요구하면 안 된다(검증 blocker).**
그건 검증 답의 성질이고, 동봉은 **자료 꾸러미에 실었다**는 뜻이라 그 값들이 **의미가 없다.**
현행도 `{type, sig, from}`만 적는다([scope-package.js:28](../scripts/scope-package.js)).
요구하면 **정상 동봉이 전부 거부되거나 가짜 값을 만들어야 한다.**

### `subjectRef` — 기존 항목 개입을 막지 않게

⚠ **`subjectEventId`를 필수로 하면 기존 장부 항목에 대한 정상 개입이 전부 거부된다(검증 blocker).**
옛 사건에는 `eventId`가 없는데 대시보드의 고정·차단·확인은 그 항목들을 가리킨다.

그래서 참조를 **둘 중 하나**로 받는다.

```
subjectRef = { eventId } | { legacySubjectHash }
```

- `eventId` — 새 규칙으로 만들어진 루트를 가리킴
- `legacySubjectHash` — `eventId`가 없는 옛 항목을 **`targetIdentity` + `sig` + 최초 시각** 지문으로 가리킴

⚠ **대상 결속이 없으면 두 프로젝트에서 같은 참조가 된다(검증 blocker).** 그리고 그 결속은
`targetKey`(경로 해시)가 아니라 **`targetIdentity`**여야 한다 — 경로 해시는 같은 경로에 다른
저장소를 갈아끼우는 경우(위 표)를 못 가른다(검증 blocker — 직전 판의 `targetKey` 결속은 자기모순). 과거 마이그레이션 등으로
같은 legacy 사건이 A와 B 장부에 함께 있으면 지문이 겹친다. 그리고 대시보드 확인 콜백은
**항목을 읽은 뒤 기록 시점에 정찰 대상을 다시 구한다**([extension.ts:4013](../src/extension.ts)) —
그 사이 다른 창에서 대상이 바뀌면 **A에서 고른 확인이 B 장부의 실재 검사까지 통과한다.**

그래서 둘을 함께 한다.

- `legacySubjectHash`에 **선택 시점 `targetIdentity`를 포함**한다
- 기록 직전 **명령에 실린 `targetIdentity`와 그 시점 실제 대상의 `targetIdentity`를 다시 대조**한다 —
  다르면 **기록 거부**. 정체성 `unknown`이면(파일 판독 불가) 역시 기록 거부(위 파일 계약 2)

기록 직전 검사도 이에 맞춘다 — **참조 대상이 같은 대상 장부에 실재**하고,
`eventId` 참조일 때만 **출처 일치**까지 본다(옛 항목은 출처 필드가 없으므로 그 검사를 못 한다).

파생·사람 사건은 근거 지문을 요구하지 않는다 — 자기 근거 파일이 없는 사건이라 `evidenceFp`가 무의미하다.

### `eventId` 유일성

- 문자 집합 **소문자 16진 16자** — 장부의 다른 id와 같은 모양(`[a-f0-9]{16}`)
- 생성 직후 **같은 파일 안에 같은 값이 있는지 검사**하고, 있으면 **최대 3회 재시도**
- 3회 다 부딪히면 **기록 거부**(조용히 중복 id를 만들지 않는다)

`subjectRef`의 `eventId`가 가리키는 대상이 유일해야 파생 사건의 결속이 성립한다.

### 옛 사건 호환

`eventId`가 없는 기존 사건은 **그대로 둔다.** 읽을 때 `legacy`로 취급하고
(승격 규칙이 이미 `legacyRepeats: 2`로 다룬다 — [ledger-events.ts:111](../src/ledger-events.ts))
새 검사를 소급 적용하지 않는다. 소급하면 멀쩡한 기존 항목이 한꺼번에 무효가 된다.

### ⚠ 마이그레이션이 출처를 세탁한다 (검증 blocker · `ab-1`)

현행 마이그레이션은 옛 사건을 `appendLedgerEvent(to, e)`로 **복사한다**
([scope-ledger-migrate.js:40](../scripts/scope-ledger-migrate.js)).
그런데 위에서 정한 대로 중앙이 `eventId`·`originRepoKey`·`ts`를 덮으면,
그 사건은 **현재 대상에서 방금 발생한 것처럼 다시 기록된다.** 정상 마이그레이션이 오귀속을 만든다.

**`legacy-import`는 별도 파일에 둔다.**

⚠ **같은 장부 파일에 넣고 필드만 붙이면 안 된다(검증 blocker).** 현행 파서는 모르는 필드를
**그냥 무시하고 정상 사건으로 받는다**([ledger-events.ts:83](../src/ledger-events.ts)).
그리고 `ledgerForPackage`는 파일 전체를 곧장 `deriveLedger`에 넘기며
([scope-package.js:21](../scripts/scope-package.js)), `miniLedgerEntries`
([contract-lib.js:2865](../bridge/contract-lib.js))와 `ledgerCouplingCandidates`
([contract-lib.js:2956](../bridge/contract-lib.js))도 격리 표시를 **검사하지 않는다.**
표시만 붙이면 격리분이 정찰 자료와 검증 동봉에 **그대로 들어간다.**

- 마이그레이션 산출물은 **`map-ledger-quarantine/<대상키>.jsonl`** 이라는 **다른 파일**로 간다
- 활성 장부를 읽는 어떤 경로도 이 파일을 읽지 않는다 — **경로가 달라서** 안 섞인다
- 각 줄에 `importedFrom`(원 장부 키)과 `legacyEventHash`를 남긴다
- 살아나려면 2단계 재입증을 거쳐 **활성 장부에 현재 출처가 박힌 새 제안**으로 들어간다

즉 마이그레이션은 **옮기는 일이 아니라 다른 서랍에 넣어두는 일**이 된다.
표시 기반 걸러내기는 소비자를 하나라도 빠뜨리면 뚫리므로 쓰지 않는다.

### 격리 파일의 유일한 독자 — 없으면 자료가 죽는다

⚠ **지금 코드에는 이 파일을 읽는 곳이 없다(검증 지적).** 재입증기를 함께 만들지 않으면
마이그레이션이 "성공"으로 끝나고 **자료는 영영 비활성으로 남는다.** 삭제는 아니지만
**"이관 완료"로 오인할 운영 경로**가 생긴다.

| 항목 | 규약 |
|---|---|
| 독자 | **재입증기 하나뿐.** 활성 장부를 읽는 어떤 경로도 이 파일을 열지 않는다 |
| 발동 | 마이그레이션 직후 1회 + 지도 갱신 사건마다 1회(같은 자리에서 정찰 재지시가 판정되는 시점) |
| **완료 키** | **`(targetIdentity, importedFrom, legacyEventHash)`** — 문서 전체에서 이 3요소가 유일한 재개 키다. `basis`는 넣지 않는다(아래) |
| 시도 키 | `(완료 키, targetBasis)` — 같은 basis에서 두 번 시도하지 않기 위한 것 |
| 상한 | 1회 발동당 처리 건수 상한을 둔다(값은 실측 뒤 확정 — 근거 없는 숫자를 지금 넣지 않는다) |
| **순서** | **지속 커서**로 돈다. 실패 항목은 건너뛰고 다음부터 이어간다 |
| 실패 | `unknown`·실패는 **격리 유지**하고 시도 횟수만 센다. 3회 연속 실패면 그 항목은 **쉼**(다음 지도 갱신까지) |

**완료 기록은 원자적으로, 대상 정체성에 결속해서 남긴다(검증 [주의]).**
새 제안을 활성 장부에 쓴 **뒤에** 완료를 표시하면 그 사이 중단 시 같은 제안이 다시 만들어진다.
완료 키는 위 표의 **`(targetIdentity, importedFrom, legacyEventHash)`** 그대로다(다른 표기 금지 —
검증 [보완]: 표와 본문이 다른 키를 말하면 구현이 갈린다). **새 제안 기록과 완료 표시를 한 잠금
안에서** 하고, 새 제안에도 같은 3요소를 저장해 재개 판정이 제안 실물로 돈다.
중단되면 다음 발동이 **새 제안 존재 여부로** 판정해 이어간다.

⚠ **멱등 키에 `basis`를 넣으면 안 된다(검증 지적).** 지도가 갱신되면 `targetBasis`가 바뀌고,
그러면 **이미 성공한 사건의 키도 바뀌어 같은 제안이 반복 생성된다** — 장부가 부풀고 계측이 왜곡된다.
그래서 **성공 계보는 `basis`와 무관한 완료 키**로 잠그고, `basis`는 **시도 중복만** 막는 데 쓴다.

⚠ **앞쪽 실패가 상한을 다 먹으면 뒤쪽이 영원히 대기한다(검증 지적).**
그래서 순서를 **지속 커서**로 두어 매번 같은 앞머리부터 시작하지 않게 한다.
| 상태 표시 | 격리 건수와 마지막 재입증 결과를 **읽기 전용 영수증**으로 남긴다 — 사람 행동을 요구하지 않는다 |

## 3. 씨앗 추출·검색 규칙과 상한

### 추출 대상 (요청문에서)

| 종류 | 규칙 | 예 |
|---|---|---|
| 경로 | 확장자를 가진 상대경로 | `src/extension.ts` |
| 백틱 토큰 | 백틱 안의 공백 없는 2~80자 | `withContract` |
| 식별자 | 낙타등·밑줄 표기 3자 이상 | `mapAttachSurface` · `verify_guard` |
| 따옴표 인용문 | 따옴표 안 3~80자 | "설치 안내 문구" |

⚠ **"모양 규칙만으로 일반어가 걸러진다"는 틀렸다(검증 지적).**
따옴표 안의 *"고쳐줘"*는 인용문 규칙에 **걸리고**, `true`·`error`·`test` 같은 흔한 토큰도
백틱 규칙을 **통과한다.**

고정 불용어 목록은 만들지 않되, **일반성 필터**를 둔다.

⚠ **직전 안의 '문서 빈도 20% 초과면 버린다'는 소규모 저장소를 망가뜨린다(검증 blocker).**
파일이 1~4개면 어떤 씨앗도 최소 한 파일에 나오므로 빈도가 **25~100%**다. 그러면 **모든 씨앗이 버려지고
요청 의도 축이 항상 빈다.** 개인용 소규모 프로젝트는 지원 범위 안이라 확정적 오작동이다.

**버리지 않고 감점한다.**

| 필터 | 규칙 |
|---|---|
| 흔함 감점 | 씨앗 점수에 `log(전체 파일 수 / 그 씨앗이 나온 파일 수)`를 곱한다 |
| 최소 말뭉치 | 검색 대상 파일이 **20개 미만이면 이 감점을 아예 적용하지 않는다** — 표본이 없으면 빈도는 의미가 없다 |
| 문자 다양성 | 서로 다른 문자가 3종 미만이면 버린다(`aaa`·`===` 류) |
| 예약어 제외 | 대상 언어의 예약어·기본 리터럴은 씨앗으로 안 쓴다 |

⚠ **정직 표기 두 가지.**
- 이 문서 머리에 *"새 숫자를 지어내지 않는다"*고 썼는데, **문자 3종·재시도 3회·최소 말뭉치 20개는
  기존 코드에서 온 값이 아니다.** 근거 없는 값임을 밝히고, 실측이 생기면 고친다.
- **예약어 제외는 '세는 규칙'이 아니라 언어별 목록이다.** 앞서 "셋 다 세는 규칙"이라고 한 것은 틀렸다.
  다만 그 목록은 언어 명세가 정한 고정 집합이라 프로젝트마다 늘어나지 않는다.

### 점수 — 부동소수를 쓰지 않는다

씨앗이 걸린 파일마다 **씨앗 종류별 가중치 합**. 경로 3 · 백틱 토큰 2 · 식별자 2 · 인용문 1.
같은 파일에 여러 씨앗이 걸리면 더한다.

⚠ **`log` 감점을 실수로 두면 실행 환경마다 결과가 달라질 수 있다(검증 지적).**
그래서 **정수로만 계산한다.**

```
점수 = Σ ( 가중치 × idf )
idf  = 말뭉치 20개 미만이면 1000
       그 외에는 round( 1000 × ln(전체 파일 수 / 그 씨앗이 나온 파일 수) )
```

⚠ **`round(1000 × ln(...))`은 여전히 부동소수 계산이다(검증 지적).** 결과를 정수로 반올림하는 것과
**계산 자체가 정수인 것은 다르다.** 플랫폼마다 `ln`의 마지막 자리가 갈리면 반올림 경계에서 값이 달라진다.

**정수 근사식을 고정한다.**

```
idf1000(N, df) = 말뭉치 20개 미만이면 1000
                 df >= N 이면 1
                 그 외 = ilog1000(N, df)
ilog1000 = 아래 '절차를 고정한다' 4단계의 정수 알고리즘이 정본(Q16 log2 근사 → ×693 ≫16)
           — 부동소수 연산을 쓰지 않는다. 이 줄은 요약이며 축척·산식은 4단계를 따른다
```

**절차를 고정한다(검증 [보완] — 이름만으론 구현이 갈린다).**

1. `q = floor(N * 65536 / df)` — 65536배 고정소수점 몫(정수 나눗셈, `df<=N`이라 `q>=65536`)
2. `b = q의 최상위 비트 위치` (= floor(log2 q)), `f16 = floor((q - 2^b) * 65536 / 2^b)` — 소수부 선형 근사(0..65535)
3. `L = (b - 16) * 65536 + f16` — Q16 고정소수점 log2(N/df) (q의 16비트 스케일을 여기서 뺀다)
4. `idf1000 = floor(L * 693 / 65536)`, 결과가 1 미만이면 **1**(바닥 — df=N이면 L=0)

정수 연산만 쓰므로 언어·플랫폼 무관 같은 값이 나온다. 근사값이라 `round(1000*ln(N/df))`와는
다를 수 있다(예: 100/10 → 2252, 실제 ln은 2303) — **순위에 쓰는 값이므로 필요한 성질은 정확도가
아니라 단조성**이고, 아래에서 전수로 잠근다.

**단조성 계약** — `df`가 작아지면 `idf1000`은 **줄지 않는다**(같거나 커진다).
유효 입력 전 범위(`1 <= df <= N <= 1500`)에서 이 성질을 확인하는 반례를 둔다.
위 산식으로 **전 범위 1,125,750건 전수 실행 — 단조성 위반 0건**(2026-08-02 실측).

**고정 테스트 벡터 20쌍** — `(N/df = 기대값)`:

```
20/20=1    20/10=693   20/1=2945   100/100=1   100/99=6
100/50=693 100/25=1386 100/10=2252 100/1=4547  500/400=173
500/250=693 500/100=1559 500/7=4238 1000/999=1 1000/500=693
1000/333=1040 1000/100=2252 1500/1500=1 1500/750=693 1500/1=7252
```

- `idf`는 **1000배 고정소수점 정수**다 — 합산이 전부 정수라 환경 차가 없다
- `df == N`이면 `ln(1) = 0`이라 **`idf`가 0이 된다.** 그때는 **`idf = 1`로 바닥을 둔다** —
  "사라지지는 않는다"는 문구를 지키려면 바닥이 필요하다(직전 안은 이 경우 0점이 되어 문구와 어긋났다)
- **씨앗이 하나도 맞지 않아 합계 0점인 후보도 목록에서 지우지 않는다.** 순위만 뒤로 간다
  (매칭된 씨앗은 바닥 1 덕에 항상 1점 이상을 남기므로, 0점은 무매칭에서만 나온다)
- **동점은 경로 사전순** — 비교 전에 경로를 슬래시 통일·NFC 정규화하고, **대소문자를 보존한 채 코드 포인트 순서**로 견준다(로캘 의존 비교 금지)

### sink 금지 (씨앗 원문·검색어·매칭 사유)

정찰 provider · MAP 문안 · 장부 사건 · `carrier` · note · 노출 사건 ·
stdout · stderr · 진단·통계 · 예외 문자열 · 캐시·임시파일.

**기존 동봉 표면(경로·note·edge 줄·결합 후보 원문·관찰 신호)은 지금처럼 그대로 나간다 —
retrieval이 거기에 씨앗 필드를 새로 추가하지 않는다는 것이 계약이다**
([MAP-RETRIEVAL-DESIGN.md:47~50](MAP-RETRIEVAL-DESIGN.md) 동일 문구). '경로만 나간다'는 직전 표현은
부정확해 폐기한다 — **MAP note·결합 문구에 민감 내용을 두면 기존 표면으로 이미 나간다.**

## 4. 노출 스냅샷 형식과 지표 정의

### 스냅샷

```
{ targetIdentity, askId, mapGenFp, retrievalVer,
  candidates: [ { kind, id, axis, paths, metricEligible } ] }
```

- `kind` — `node` · `edge` · `coupling` · `signal`
- `axis` — `intent` · `changed` · `ledger` · `neighbor`
- `paths` — **실제로 렌더링된 경로만** (정규화 후)
- `metricEligible` — `paths`가 비어 있지 않으면 `true`

### `metricEligible` 판정 — 종류가 아니라 **실제 렌더링 결과**로

⚠ **종류로 정하면 틀린다(검증 지적).** 결합은 프롬프트에 **앞 200자만 실리므로**
([contract-lib.js:2760](../bridge/contract-lib.js)) 경로가 뒤쪽에 있으면 **잘려 나간다.**
그런데도 `coupling`이라는 이유로 적격 처리하면 **분모가 부풀고 인용률이 낮게 나온다.**

> `metricEligible` = **그 후보의 최종 문자열에서 정규화된 경로가 실제로 보이는가**

⚠ **전체 프롬프트를 사후 검색하면 안 된다(검증 지적).** 같은 경로가 사용자 요청문이나 다른 후보에
있으면 **잘려나간 결합까지 적격으로 오인한다.**

**후보별로 판정한다.** `renderV2Slice`와 `scoutCouplingAttach`가 후보마다
**최종 문자열과 그 안에 실제로 노출된 경로 집합**을 함께 반환하고, `withContract`가 그것을
그대로 `carrier`에 기록한다([codex-bridge.js:90](../bridge/codex-bridge.js)).
판정 시점은 **후보 문구를 만든 직후, `carrier` 저장 전**이다. 종류는 참고 정보로만 남긴다.

| `kind` | 대개 | 왜 |
|---|---|---|
| `node` | 적격 | 경로가 줄 앞에 그대로 나옴 |
| `coupling` | **경우에 따라** | 200자 절단으로 경로가 잘릴 수 있음 |
| `edge` | 비적격 | 양 끝 이름만 나오고 뒷받침 경로는 출력 안 됨 |
| `signal` | 비적격 | 인용할 경로가 아예 없음 |

### 두 지표

```
인용률       = |적격 후보 중 인용된 것| / |적격 후보|
동봉 밖 인용률 = |인용됐는데 적격 후보에 없던 경로| / |인용된 경로 전체|
```

인용 추출은 `citedResolvedPaths`, '실제로 읽은 근거'는 `citedFilesUnseenExact` 결과와 결속한다
([codex-bridge.js](../bridge/codex-bridge.js)).

### `unknown` 조건

- 검색이 상한에 걸림
- 스냅샷 판독 실패
- `citedFilesUnseenExact`가 `checked: false`
- 적격 후보가 0건 (분모 0)

**`unknown`은 낮은 점수가 아니다.** 평균에서 제외하고 건수만 센다.

## 5. 압축의 참조 보존 계약

### 구조

**모든 파생 사건은 루트 제안을 직접 가리킨다.** 파생이 파생을 가리키는 것을 금지한다 —
보존 집합이 입력 전체로 커지는 것을 구조로 막는다.

### ⚠ 압축 단위는 '현재 루트'가 아니라 '원래 sig' (검증 blocker)

`deriveLedger`는 **활성 별칭 그래프를 먼저 만든 뒤** 모든 사건을 현재 루트로 합친다
([ledger-events.ts:147](../src/ledger-events.ts)). 그래서 루트 단위로 뭉치면
**합쳐진 `counts`·`text`·확인 이력이 어느 `sig` 것이었는지 잃는다.**

실측 반례 — `p←s` 별칭 상태는 `p` 하나로 합쳐져 `verified`, `counts={proposed:2, confirmed:2}`였다.
거기에 `unalias` 하나를 붙이자 **`p`는 `inferred`, `s`는 `verified`로 다시 갈라졌다.**
루트 단위 스냅샷은 **확인 2건이 `s` 소유였다는 사실을 잃어** 이 분리를 재현하지 못한다.

따라서 압축 단위를 바꾼다.

- **원래 `sig`별로 전이 요약을 만든다** — 합치지 않는다
- **별칭 간선은 따로 보존한다** — 합병·분리를 나중에 다시 계산할 수 있게
- 확인·반박에 **합병 뒤에도 비교 가능한 append 순서**를 남긴다(전역 단조 증가 번호)

### sig별 정본 스냅샷 — 충분통계

압축은 sig마다 사건들을 **하나의 스냅샷**으로 합치되, `LedgerEntry`가 **관찰 가능하게 내보내는 모든 필드**와
이후 전이에 필요한 값을 전부 보존한다([ledger-events.ts](../src/ledger-events.ts)).

```
{ sigKey, originRepoKey, seq,        // seq = 전역 단조 append 순서(합병 뒤 비교용)
  text: { value, seq },      // 이 sig의 최초 유효 문구와 그 전역 위치 — 병합 시 루트 우선·최소 seq(아래 표)
  from: { value, seq },      // 전역 순서 첫 비어있지 않은 값(ledger-events.ts:210) — 병합=최소 seq
  firstTs: { value, seq },   // 최초 사건의 시각과 전역 위치 — 병합=최소 seq
  lastTs: { value, seq },    // 마지막이 이기는 값은 '그 값을 정한 seq'까지(아래 표)
  status, pinned, lane, autoEligible, machineEvidence, reinterpreted, rehabilitated,
  counts: { <사건 종류별 정확한 건수> },
  supersededBy: { value, seq },      // newSig — 상태만으로는 복원 불가·마지막 우선이라 seq 필요
  aliasEdges: [ { aliasSig, parentSig, net } ],   // 부모별 가중 간선 전체
  // ⚠ 증거는 '개수'가 아니라 '레코드'로 — 각각 seq를 달고 남긴다(아래 설명)
  claimed:  [ { askId, seq } ],      // 등급별 최신 임계 개수까지 (claimed 1)
  coCited:  [ { askId, seq } ],      // (co-cited 2)
  legacyTs: [ { tsId,  seq } ],      // (legacy 2)
  userConfirms: [ { seq } ], userDisputes: [ { seq } ],
  lastDispute: { seq, at },          // 마지막 유효 반박의 전역 위치
  bannedNet: n, pinnedNet: n }
```

### 순서 보존 일반 규칙 — 필드마다 땜빵하지 않는다

증거에만 `seq`를 달아도 **또 뚫렸다.** `deriveLedger`는 `lastTs`를 마지막 비-`attached` 사건으로,
`supersededBy`를 마지막 `superseded` 사건으로 **덮어쓴다**
([ledger-events.ts:204·211](../src/ledger-events.ts)).

실측 반례 — `p→q` 다음 `s→r` 순서(A)와 그 반대(B)를 만들고 `attached`로 sig별 마지막 위치와
별칭 전 출력을 같게 고정한 뒤 같은 `s→p` alias를 붙이자
**A는 `supersededBy=r`·`lastTs=…04`, B는 `supersededBy=q`·`lastTs=…03`**이 됐다.

한 필드씩 고치면 다음 필드에서 또 뚫린다. **규칙으로 닫는다.**

⚠ **"전부 마지막이 이긴다"도 틀렸다(검증 blocker).** `deriveLedger`는 필드마다 **결정 방식이 다르다.**

| 결정 방식 | 필드 | 보존해야 할 것 |
|---|---|---|
| **마지막이 이김** | `lastTs`(비-`attached`) · `supersededBy` | 그 값을 정한 **마지막 seq** |
| **가중 순계** | `pinned` · `banned` | 각 방향 사건의 **개수와 가중치**([ledger-events.ts:198·221](../src/ledger-events.ts)) |
| **우선순위** | `status` | `banned` > `superseded` > `tombstone` > `disputed` > `verified` — 순서가 아니라 **어느 조건이 성립했나**([:230](../src/ledger-events.ts)) |
| **루트 우선 + 대체는 전역 최초** | 대표 `text` | 루트 자체 첫 문구가 이김 — **루트에 문구가 없으면 전역 순서에서 처음 만난 별칭 문구가 대체**([:206~209](../src/ledger-events.ts)). 보존: 각 sig의 **최초 유효 문구와 그 seq**. 병합 = 루트 자체 문구 우선, 없으면 **별칭 첫 문구 중 최소 seq**. `autoEligible`은 그렇게 선택된 text에서 **재계산**([:220](../src/ledger-events.ts)) |
| **처음이 이김** | `from` · `firstTs` | **최초 seq** |
| **승격 가능만** | 증거 집합 | `promotableConfirm`·`promotableDispute`를 통과한 것만([:120·129](../src/ledger-events.ts)) |

실측 반례 — `p` 문구가 나중이어도 `s→p` 합병에서 **대표 문구는 `p`**였다.
`p`에 `superseded`, `s`에 나중 `tombstone`을 두고 합치면 마지막 기준으론 `tombstone`이지만
**실제는 우선순위대로 `superseded`**였다.
추가 실행 반례(확인 검증) — `p`에 자체 문구가 없고 `s`·`t`가 합쳐질 때, **`s`·`t` 문구 사건의
전역 선후만 바꿔도** 대표 `text`와 `autoEligible`이 갈렸다. sig별 스냅샷에 문구의 `seq`가 없으면
압축 후 이 순서를 복원할 수 없다(`ab-5`).

> **규칙: 스냅샷은 `deriveLedger`가 그 필드를 정하는 데 실제로 쓰는 입력을 보존한다.**
> 순서로 정하는 것만 `seq`를 달고, 순계로 정하는 것은 개수를, 우선순위로 정하는 것은 조건 성립 여부를,
> 루트 우선인 것은 루트 소속을 남긴다. **대체 후보가 여럿인 값(별칭 문구)은 후보마다 `seq`를 남겨
> 병합 뒤 전역 최초를 재현한다.**

빠뜨렸는지는 **`deriveLedger`가 내보내는 필드 목록과 스냅샷 필드 목록을 대조하는 반례**로 잡되,
목록 일치만으로는 부족하므로 **각 필드의 결정 방식별 반례**를 함께 둔다.

### 증거는 '최신 N건'이 아니라 '서로 다른 키별 최신'

⚠ **`co-cited`가 `A, B, B`인 입력은 현재 `Set(askId)` 크기 2라 `verified`**다
([ledger-events.ts:136](../src/ledger-events.ts)). 그런데 단순 최신 2건만 남기면 `B, B`가 되어
**`inferred`로 떨어진다.**

따라서 **`askId`(또는 `tsId`)별로 묶어 각 키의 최신 레코드 하나씩**을 남기고,
그렇게 만든 **서로 다른 키가 임계 개수에 닿을 때까지** 보존한다.

실측 반례 — 두 입력이 alias 전까지 sig별 결과가 **완전히 같았다**(`p`=verified, `s`=disputed,
`counts`·`lastTs`·각 sig의 마지막 append 위치까지 동일). 차이는 **`p` 확인과 `s` 반박의 전역 선후**뿐이었다.
같은 `s→p` alias를 붙이자 **확인→반박 순서는 `disputed`, 반박→확인 순서는 `verified·rehabilitated`**가 됐다.

그래서 **증거마다 `seq`를 단다.** `confirmsAfterDispute`라는 파생 집계는 없앤다 —
`lastDispute.seq`와 각 증거의 `seq`를 비교하면 **합병 뒤에도** 다시 계산할 수 있다.
집계로 미리 접으면 합병 상대의 반박 위치가 바뀔 때 재계산이 불가능하다.

**직전 안이 무손실이 아니었다(검증 blocker).** 셋이 빠졌다.

- `aliasNet: n` 하나로는 **부모별 순계 그래프와 동률 사전순 선택**을 복원 못 한다 → `aliasEdges`로 바꿈
- `legacyRepeats: n` 하나로는 **서로 다른 시각 집합**을 복원 못 한다.
  실측 반례: 같은 시각의 확인을 하나 더 붙이면 `inferred`, 새 시각을 붙이면 `verified` → `legacyTsIds`로 바꿈
- `supersededBy`가 빠져 있었다. 실측 반례: 대상만 `q`에서 `r`로 바꾼 두 입력이 **상태는 같은데
  `supersededBy` 결과가 달랐다**

`askId`·`legacyTsIds`는 **임계까지만** 보존한다(claimed 1 · co-cited 2 · legacy 2).
그 이상은 판정에 안 쓰이므로 버려도 동치가 안 깨진다 — 여기가 크기를 실제로 줄이는 지점이다.

### 동치 조건

> 압축 전후 `deriveLedger`의 **모든 관찰 가능 필드**가 같고, 이후 **어떤 정상 사건을 덧붙여도
> 상태 전이와 그 필드들이 같다.**

'상태만 같으면 된다'가 아니다 — `supersededBy`·`aliases`·`counts`까지 같아야 한다.

### 루트가 너무 많아 못 줄이는 경우

고유 루트 수가 상한을 넘으면 스냅샷도 그만큼이라 크기가 안 준다. **둘을 함께 쓴다.**

1. **오래된 루트를 별도 보존 계층으로 이관** — 활성 장부에는 최근 것만, 이관분은 `deriveLedger`가 필요할 때만 읽음
2. 그래도 못 줄면 **`compactFloor` 표식**을 남겨 다음 append의 전량 재시도를 막는다.

⚠ **해제 조건을 '사건 수 10% 증가'로 두면 안 된다(검증 지적).** 그 값은 기존 코드에서 유도된 것도 아니고
**압축 가능성과 결속돼 있지도 않다.** 압축 불가능한 사건이 10% 쌓이면 헛된 재압축을 깨우고,
반대로 **압축 가능한 상태 변화 한 건**은 10%에 한참 못 미쳐 오래 지연된다.

⚠ **지문만으로도 안 된다(검증 지적).** 이미 `banned`인 루트에 `banned` 사건이 계속 쌓여도
**지문은 안 바뀌므로 영원히 압축되지 않고** 원시 로그만 커진다. 반대로 정확한 `counts`를 지문에 넣으면
**매 append마다 바뀌어** 억제가 사라진다.

**지문과 누적량을 함께 쓰는 히스테리시스**로 한다.

```
compactFloor = { at, compactabilityFp, rawBytesAt, rawEventsAt, snapshotGen }
compactabilityFp = 해시( sig별 [상태 · 보관 계층 · 충분통계 임계 도달 여부] )
```

**셋 중 하나라도 참이면 해제**한다.

- `compactabilityFp`가 바뀜 — 압축할 거리가 실제로 생김
- **표식 이후 늘어난 원시 바이트가 예상 절감량을 넘음** — 쌓이기만 해도 결국 한 번은 돈다
- **보관된 루트를 가리키는 새 사건이 들어옴** — 그 루트를 즉시 재수화하고 지문 재계산

*예상 절감량*은 마지막 압축에서 실제로 줄인 양으로 둔다 — 새 숫자를 만들지 않는다.

⚠ **첫 `compactFloor`이거나 마지막 절감량이 0이면 그 값이 0이라, 한 건만 붙어도 다시 전량 압축을
시도한다(검증 지적).** 그래서 **바닥을 둔다.**

⚠ **'2,000건에 해당하는 바이트'는 실행 가능한 정의가 아니다(검증 [주의]).** 건수를 바이트로 바꾸는
산식이 없으면 비교 자체가 안 된다. 그래서 그 시점 장부의 평균 줄 길이를 쓴다.

```
바닥 = 2000 × floor(현재 파일 바이트 / 현재 사건 수)
```

건수 상한 둘과 실제 파일 크기에서만 나오므로 새 숫자가 아니다.
사건이 0건이면 압축 자체가 안 도므로 이 식이 불릴 일이 없다.

### 반례

- 12,000건 초과에서 압축 실행 → 고아 없음 · 크기 감소 · `deriveLedger` 동치
- 압축 직후 append 반복 → 전량 재계산이 억제되는지
- 고유 루트 12,001개 → 이관 후 활성 장부가 줄고 `compactFloor`가 붙는지
- 반박 뒤 확인 → 복권이 압축 전과 같게 동작하는지

## 아직 정하지 못한 것 (정직)

- **씨앗 검색 시간 상한** — 저장소 규모별 실측이 먼저다. 그 전에는 나머지 상한으로만 묶는다
- **관계 증명 어댑터** — 지금 둘뿐이라 나머지 열 관계는 제안 단계에 머문다. 필요할 때 하나씩 추가
- **`mapGenFp`·`retrievalVer`를 무엇으로 채울지** — 지도 세대 지문과 버전 문자열의 출처를 구현 시 확정

**이 셋을 뺀 나머지는 구현에 들어갈 수 있다.** 값이 더 필요하면 그때 이 문서를 고친다.
